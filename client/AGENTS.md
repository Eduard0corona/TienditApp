# Reglas del cliente

- Usa `src/api/axios.ts` y módulos `src/api`; no crees otras instancias Axios ni disperses `fetch`.
- React Router/guards controlan UX, no seguridad. Backend sigue siendo autoridad de tenant, permisos y capabilities.
- No calcules de forma autoritativa estados, totales, impuestos, saldos o existencias.
- Mantén TypeScript estricto; no introduzcas `any` sin justificación localizada.
- Los enums del dominio salen del contrato: `npm run api:types` genera `src/api/generated/schema.ts` y `src/api/generated/enums.ts` (no se editan) y `src/types/index.ts` los reexporta. No copies un enum a mano.
- Reutiliza componentes comunes, hooks y tipos; divide componentes grandes solo en refactors focalizados.
- Colores solo con los tokens de `src/assets/css/theme.css` y la paleta del tema del negocio (`utils/businessThemes.ts`): un estado usa `ta-chip-*` o los colores de estado, nunca el acento (`bg-primary`), y la acción principal es `btn-primary`. Un tema nuevo entra con todos sus pares AA en `businessThemes.test.ts` (ADR 0010). El texto sobre el acento usa `--ta-on-accent` (o `--tt-on-accent` donde el acento es el tono claro en los dos modos), nunca blanco fijo: en modo oscuro el acento es claro.
- El foco del teclado es el anillo de `theme.css` (`--ta-focus-ring`, `--ta-focus-ring-width`, `--ta-focus-ring-offset`): no lo quites con `outline: 0` o `none` (`assets/css/focusRing.test.ts` falla) ni le sumes un resplandor. Donde alrededor se cortaría (una fila que se desplaza, un elemento a todo el ancho de una lista), `--ta-focus-ring-offset` negativo lo pone por dentro si el elemento no tiene relleno propio bajo el anillo; si lo tiene (un chip de Vender con `btn-primary`), deja espacio en la fila como `.sell-chips`. Una regla con `:focus-visible` no lleva otros selectores en su lista: Safari antes de 15.4 la descarta entera.
- Textos con mayúscula solo al inicio y en nombres propios, "negocio" (no "empresa") y "correo" (no "email"). Una pantalla tiene una sola acción principal y no repite las de la barra superior o la de pestañas; las migas (`PageTitle` con `parent`) solo van en las pantallas de detalle.
- Una foto que puede faltar (producto, logo) usa `PhotoOrInitial`: la inicial donde falta mientras otras tengan foto. Una fila de chips que se desliza usa `useScrollFade` con `.ta-scroll-fade`; una lista que se desplaza hacia abajo, `useScrollFade(…, 'y')` con `.ta-scroll-fade-y`.
- Una lista usa `DataTable` con una sola barra: búsqueda, filtros (`filters`, cada uno en `DataTableFilter`) y su acción (`toolbarEnd`); la paginación va abajo. Una acción de fila dice con texto lo que hace, y su `aria-label` empieza con ese texto y nombra el registro; un botón que solo lleva ícono necesita `aria-label`.
- Conserva estados loading, empty, error y success y accesibilidad básica de formularios/controles. El lint incluye `eslint-plugin-jsx-a11y`: cada etiqueta va con `htmlFor`/`id` (con el índice dentro de listas) o envuelve su control, y lo clicable es un `button` o un enlace real (`utils/a11y.ts` `asButton` solo para bloques que no caben en un botón). Un `Modal` u `Offcanvas` se nombra con su título: `aria-labelledby` con el `id` (`useId`) de su `Title`, o `aria-label` si no tiene título; el lint lo exige.
- No guardes access/refresh tokens o secretos de integración en almacenamiento accesible a JavaScript. El access token actual permanece en memoria.
- Limpia conexiones SignalR y preserva aislamiento tenant.
- Ejecuta `npm ci`, `npm run lint`, `npm test` y `npm run build`; `package-lock.json` no debe cambiar por validación.
- Un cambio de CSS global (`assets/css`, la plantilla, el marco de la app) corre las escenas visuales (`visual/README.md`): `npm run visual:baseline` y `npm run visual:compare`, y el PR dice cuántas escenas cambiaron y por qué. Una escena nueva busca por rol, etiqueta o texto, nunca por las clases de la plantilla, responde cada petición que hace la pantalla (las escenas fallan con una petición sin respuesta) y pasa dos corridas seguidas contra el mismo build.
- El marco de la app (barra superior, menú lateral, contenido, pie, barra de pestañas y modo enfocado) vive en `src/assets/css/shell.css`, con clases `ta-*` y variables `--ta-*`; no vuelvas a usar las clases del marco de Hyper (`navbar-custom`, `leftside-menu`, `side-nav-*`, `content-page`, `page-title-box`…) ni sus atributos (`data-sidenav-size`, `sidebar-enable`).
- Bootstrap se compila desde Sass (`src/assets/scss/bootstrap.scss`): un valor cambia en `_variables.scss` o `_variables-dark.scss`, y lo que la app agrega a un componente de Bootstrap va en `_additions.scss`. No copies CSS compilado ni edites `node_modules/bootstrap`. Un cambio ahí, o subir de versión `bootstrap` o `sass` (van con versión exacta), corre las escenas visuales como cualquier CSS global.
- Una clase que solo tenía Hyper (la lista está en `assets/css/hyperClassNames.json`) necesita su regla en `src/assets/css/components.css`; `assets/css/hyperClasses.test.ts` falla si el código usa una sin regla. No la escondas en su lista `NOT_CLASSES`: esa lista es solo para palabras que no se usan como clase.
- `scripts/check-bundle.mjs` compara lo que baja la primera visita con `bundle-budget.json`: si un cambio lo hace crecer, sube el presupuesto en el mismo PR y dice por qué; si lo reduce, lo baja.
- Las pruebas (Vitest y Testing Library) viven junto al código como `*.test.ts(x)`: utilidades que reflejan reglas de la API, la matriz de acceso y componentes con dinero, existencias o errores.
